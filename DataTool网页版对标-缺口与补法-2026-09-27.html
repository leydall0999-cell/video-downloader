把竞品官网的网页功能逐项拆出来，与「视频工坊」网页版现状一一对照，给出可直接开工的补法清单。

一句话结论

他们的网页版功能面其实比我们窄——没有去水印、没有音乐/图片转换、没有本地 ASR、没有抠图，全靠「在线解析 + 字幕 + AI 总结」三件事撑门面。 我们后端能力（21 个路由模块）明显更厚，真正缺的不是能力，而是把已有能力摆到网页上、并让搜索引擎和海外用户找得到。

所以「补」的重点不是照抄功能，而是三块：① 该亮的没亮（下载页全写"开发中"、全站禁收录）、 ② 对标缺口（AI 视频总结、字幕导出多格式/任务列表）、③ 增长面（多语言、每平台落地页、扩展页）。

三、缺口清单（按「值不值得做」排序）

优先级缺口为什么值得补怎么补
P0 下载页写着「开发中」，但 macOS 版其实已经可用（v1.0.29 已构建装机） 自己人看到的第一个页面在说谎，白白丢掉最直接的转化入口 把 web/download/index.html 的卡片换成真实安装包链接 + 版本号，未就绪的才保留"开发中"
P0 robots.txt 全站 Disallow: /，等于告诉所有搜索引擎"别来" 他们靠 SEO 落地页吃自然流量，我们是 0；这条不放开，后面做多少落地页都白做 放开抓取 + 加 sitemap.xml（把首页、/download、各落地页列进去）
P1 字幕导出只有 SRT / TXT；翻译只有单模式、目标语言靠手打 对标最直接的差距，且改动全在 #subtitleView 内，不碰后端 补 VTT / JSON 导出；翻译加 双语 / 仅译文 / 仅原文 三模式；目标语言改下拉
P1 缺「AI 视频总结」入口（他们导航四大项之一） 我们已有 LLM 配置 + 字幕内容，做文本总结是"顺手接上"，差异化明显 新增「AI 总结」面板：基于已有字幕 → 总结 / 问答 + 提示词库 + 内容预算（对标 6000 字默认）
P1 字幕提取是"一次一单"，没有任务列表 批量场景（一次丢十个链接）体验差距最大的一环 做任务列表：全部/进行中/已完成/失败 + 批量导出/删除，接已有 /api/tasks
P1 个人中心无「购买中心 / 订单记录」 后端 /api/member/plans 与 auth.py 的 purchases 数据都现成，只差前端 在 #profileView 加两块：套餐展示（走 member/plans）+ 兑换/订单记录（走已有 purchases）
P2 无浏览器扩展安装页 已有百度网盘油猴脚本基础（baidu-tampermonkey/），可先出安装页 新增扩展介绍/安装页，引导装脚本或打包扩展
P2 无每平台 SEO 落地页 / 博客 / FAQ 他们靠这套吃自然搜索；我们需要同类页面承接关键词 先做 3~5 个高频平台落地页（YouTube / B站 / 抖音 / 小红书 / TikTok）+ FAQ
P2 单语言（zh-CN） 他们 30 语言面向全球；我们若做海外才有必要，否则性价比低 先抽出文案字典做 i18n 骨架，按需补 en 一种，别一上来 30 种
P2 Android / iOS / 应用商店分发 他们有 Android APK + Microsoft Store；属产品线扩张，不是网页缺口 先只在下载页如实标注现状，产品线单独立项

四、建议怎么走

我的建议：P0 两件立刻做，P1 里挑「字幕增强 + AI 总结」一起做，其余看运营节奏。

  1. P0-1 下载页说实话：macOS 已可用就该给真实下载；把「加急开发中」只留给真正没做的平台。改动只在 1 个 HTML 文件。
  2. P0-2 放开收录 + 建 sitemap：这是所有 SEO 动作的前置，不先做后面全白费。改动 2 个文件。
  3. P1 字幕导出与翻译增强：VTT/JSON + 双语/仅译文/仅原文 + 目标语言下拉。纯前端，风险最低，对标感最强。
  4. P1 AI 视频总结：复用已有字幕产物 + LLM 配置，新增一个面板，是真正"他们有我无"的功能差异。
  5. P1 字幕任务列表 / 购买中心：后端数据都现成，属"把已有能力摆上去"，可批量一起做。

P2 的落地页/多语言/扩展页属于增长投入，建议等 P0+P1 上线拿到数据后再决定要不要压资源——尤其多语言，别一上来做 30 种。

顺带发现的两处"名不符实"（建议一并修）

  • web/download/index.html 声称"安装包托管于 GitHub Releases"，但页内没有任何真实下载地址，四张卡全是占位按钮。
  • 页尾那句"支持 macOS / Windows / Android / iOS"与实际"全部开发中"自相矛盾。
